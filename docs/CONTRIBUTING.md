# Контрибьюшн в LayoutFixer

Короткий гайд для агентов и разработчиков. Контекст проекта и архитектура —
в `AGENTS.md` и `docs/ARCHITECTURE.md` соответственно. Прочти их ПЕРВЫМИ.

---

## Перед правкой

1. **Прочитай `AGENTS.md` → «Критические инварианты».** Почти любая
   «очевидная» правка логики переключения ломает один из уже исправленных
   кейсов. Их 10+, и каждый стоил релиза.
2. **Прочитай `CHANGELOG.md` за последние 5–6 версий.** Там человеческим
   языком описано, что и почему менялось.
3. **Убедись, что понимаешь разницу между Live и Final фазами** (см.
   `docs/ARCHITECTURE.md` §4–5). Они намеренно устроены по-разному.

---

## Сборка и проверка

```powershell
# Установить локальный .NET SDK (один раз):
.\.dotnet-install.ps1

# Быстрая проверка компиляции:
.\.dotnet\dotnet.exe build src\LayoutFixer\LayoutFixer.csproj

# Собрать релиз:
.\build.ps1                 # все 3 варианта
.\build.ps1 -Variant win-x64
```

Сборка должна давать **0 ошибок, 0 предупреждений**.

Для запуска отладочной сборки без риска для своего профиля задай папку данных:
`$env:LAYOUTFIXER_DATA_DIR = "$env:TEMP\lf-test"` перед запуском.

---

## Тестирование

```powershell
.\.dotnet\dotnet.exe test tests\LayoutFixer.Tests\LayoutFixer.Tests.csproj
```

Тесты должны проходить всегда (`build.ps1` запускает их перед упаковкой).
Решения о раскладке проверяются симуляцией набора по клавишам через
`LayoutDecisionEngine` (`tests/LayoutFixer.Tests/TestEngine.cs`). Новый
исправленный баг → новый тест в `DecisionEngineTests` или `InputPipelineTests`.

Любую правку порогов (`NgramDecisionOptions`), ручных списков или порядка
решений меряй инструментом `tools/LayoutFixer.Tools eval` на частотных списках
и сравнивай с таблицей в `tools/LayoutFixer.Tools/README.md`. Ложное
исправление правильного слова хуже пропуска.

Путь хука (подавление клавиш, `SendInput`, переключение раскладки) автотестами
не покрыть: собственный `SendInput` хук игнорирует. Его проверяют двумя путями:

### A. Чтение кода + лог
Включи в настройках «Отладочный журнал», воспроизведи кейс, посмотри
`%AppData%\LayoutFixer\debug.log`. По логу видно:
- каждую клавишу (`Observe: VK=… -> 'x'`);
- решения `TryLiveConvert HIT` / `FinalConvert` / `TryFinalDecision`;
- состояния буфера (`bufferAfter=…`);
- все hold-off'ы и guards.

### B. Прослеживание сценария
Для любого кейса проследи по коду:
1. Что физически печатает пользователь и в какой раскладке.
2. Какой `token.Text` и `convertedText` получаются.
3. Какая ветка `TryLiveConvert`/`FinalConvert` сработает.
4. Не нарушает ли это инвариант из `AGENTS.md`.

## Релиз

1. **Бамп версии** в `src/LayoutFixer/LayoutFixer.csproj` (`<Version>`):
   - `MAJOR.MINOR.PATCH`; мелкий фикс — `PATCH`, существенное — `MINOR`.
2. **Запиши `CHANGELOG.md`** новой записью сверху, по-русски, с рубриками
   `### Добавлено / ### Изменено / ### Исправлено / ### Удалено`.
3. **Собери** `.\build.ps1` — все 3 варианта появятся в `publish/`.
4. (Опционально) Приложи снапшот `debug.log` к релизу, если менял логику.

## Что НЕ делать

- **Не возвращай полные словари** (`50000-russian-words-cyrillic-only.txt`,
  `30k-english.txt`) в `LayoutFixer.csproj` и не восстанавливай
  `WordDictionaries`-класс. От них сознательно ушли в 1.5.0 в пользу
  предгенерированных триггеров.
- **Не смешивай UserDictionary и UserReplacements.** Это разные сущности с
  разной семантикой (см. `docs/ARCHITECTURE.md` §6).
- **Не делай `Sleep` и не вызывай UI Automation внутри клавиатурного хука.**
  Live и final (через `InputBatch`) работают в хуке и переключают раскладку
  `PostSwitchTo`; проверки фокуса — только в фоне (`InputContextGuard`).
- **Не отправляй замену несколькими вызовами `SendInput`** — только одним
  массивом (`TextInputSender`).
- **Не пиши пользовательские файлы напрямую** — только через `AtomicFile`.
- **Не правь `KeyboardBuffer.Separators` без необходимости** — от него
  зависит корректность токенизации и `ReplaceTail`.
- **Не встраивай данные чужих программ.** Новые таблицы и ресурсы — только
  собственные или с совместимой лицензией, с записью в `NOTICE.md`.

## Стиль кода

- `.editorconfig`: UTF-8, CRLF, 4 проброса, финальный newline.
- Имена методов/свойств — PascalCase; локальные — camelCase.
- Комментарии — на английском (как в существующем коде) ИЛИ на русском в
  CHANGELOG/доке. Внутри `.cs` придерживайся английского, чтобы совпадать с
  окружением.
- Логирование: `Logger.Log(...)` в стиле существующих вызовов — каждый
  нетривиальный путь в `TryLiveConvert`/`FinalConvert` должен оставлять след.
