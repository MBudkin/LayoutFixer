## TL;DR

**LayoutFixer** — Windows-трей утилита (C#/.NET 10, WinForms), которая
автоматически исправляет русско-английские опечатки раскладки и переключает
системную раскладку. Версия сейчас **1.11.0**. Репозиторий:
<https://github.com/MBudkin/LayoutFixer>, сборка — скриптом `build.ps1`.

Если нужно быстро войти в курс дела — прочти раздел **«Архитектура»** ниже и
`docs/ARCHITECTURE.md`. Если нужно поправить логику переключения — раздел
**«Критические инварианты»** (там список багов, которые уже когда-то
сделали и не хотят повторять).

## Как собрать

```powershell
# Установить локальный .NET 10 SDK (один раз):
.\.dotnet-install.ps1

# Собрать все 3 варианта (версия читается из csproj автоматически):
.\build.ps1

# Только один вариант:
.\build.ps1 -Variant win-x64     # self-contained single-file ~73 МБ
.\build.ps1 -Variant framework   # framework-dependent ~1 МБ
.\build.ps1 -Variant source      # чистый снапшот для публикации

# Быстрая проверка компиляции без упаковки:
.\.dotnet\dotnet.exe build src\LayoutFixer\LayoutFixer.csproj

# Модульные тесты (обязательно перед релизом):
.\.dotnet\dotnet.exe test tests\LayoutFixer.Tests\LayoutFixer.Tests.csproj
```

Артефакты кладутся в `publish/LayoutFixer-<version>-<variant>/`. Локальный
`.dotnet/` в git не попадает (см. `.gitignore`).

## Как запустить для отладки

`LayoutFixer.exe` ставит **глобальный низкоуровневый клавиатурный хук**
(`WH_KEYBOARD_LL`) — без интерактивной сессии Windows он не имеет смысла.
Переменная окружения `LAYOUTFIXER_DATA_DIR` переносит настройки/словари/журнал
в другую папку — так можно запускать отладочную сборку, не трогая профиль
пользователя. Тестировать логику можно тремя путями:

1. **Собрать win-x64, запустить `.exe`, включить в настройках «Отладочный
   журнал»** — лог пишется в `%AppData%\LayoutFixer\debug.log`. По нему видно
   каждую клавишу, состояние буфера и решения `TryLiveConvert` /
   `FinalConvert`. Это главный способ отладки поведенческих багов.
2. **Читать код** — логика хорошо покрыта `Logger.Log(...)`, и по логам из
   баг-репорта обычно легко поставить точный диагноз.

3. **Модульные тесты и инструмент оценки.** `tests/LayoutFixer.Tests` проверяет
   решения `LayoutDecisionEngine` симуляцией набора по клавишам (live + final),
   инварианты из списка ниже и `InputBatch`. `tools/LayoutFixer.Tools eval`
   прогоняет десятки тысяч слов и показывает ложные срабатывания/полноту —
   **любое изменение порогов, таблиц или порядка решений проверяй им.**

> Внешний ввод (`SendInput`) хук игнорирует (`LLKHF_INJECTED`), поэтому
> сквозной автотест «нажал клавишу → увидел текст» невозможен: путь хука
> проверяется вручную по `debug.log`.

## Архитектура (кратко; подробнее в docs/ARCHITECTURE.md)

Поток данных при нажатии клавиши:

```
KeyboardHook (WH_KEYBOARD_LL, на UI-потоке)
   │ KeyObserved(VK, scanCode)
   ▼
TrayApplicationContext.KeyObserved-лямбда  ← ОРКЕСТРАТОР
   │
   ├─ KeyboardBuffer.Observe()    накапливает видимые символы, возвращает reset?
   │
   ├─ поле пароля (InputContextGuard): буфер сброшен, клавиша не пишется
   │
   ├─ если терминатор (Space/Enter/Tab/—):  HandleTerminatorInHook() [СИНХРОННО]
   │     └─ InputBatch: ApplyReplacement() → FinalConvert()
   │        → FixAccidentalCapsLock() → FixTwoInitialCapitals()
   │        → AutoCapitalizeLastWord()
   │        есть изменения → Suppress + ОДИН SendInput (BS + текст + разделитель)
   │
   └─ иначе если AutoMode и IsLiveEligibleKeystroke(vk) и AutoEditsAllowed():
         └─ TryLiveConvert()    синхронно на хуке, args.Suppress=true при HIT
```

**Две фазы автоконвертации:**

| Фаза | Когда | Где | Особенности |
|---|---|---|---|
| **Live** | во время ввода слова | `TryLiveConvert` | синхронно на потоке хука; N−1 backspace; подавляет клавишу-триггер (`args.Suppress`) |
| **Final** | после разделителя | `FinalConvert` | синхронно в хуке через `InputBatch`; разделитель подавляется и пересылается вместе с заменой; может revert'иться Pause'ом |

**Порядок final-решения** (в `LayoutDecisionEngine.TryFinalDecision`):
1. UserDictionary (приоритетный словарь раскладки): visible в текущей → оставить;
   converted в другой → заменить+переключить; обе → skip.
2. Адреса (`@`, `://`, `www.`), идентификаторы (`VkShift`, `iPhone`) и
   converted = имя клавиши (`ctrl`) → оставить.
3. Частоты коротких слов (2–4 буквы, `ShortWordRanks`): `yt`→`не`; `it` остаётся.
   Короткая аббревиатура ВСЕ-ЗАГЛАВНЫМИ без частотного решения → оставить.
4. Точные совпадения FinalTriggers (+ `final-words-en`) + LiveTriggers.
5. Буквенные n-граммы (`NgramModel`, относительные оценки): convert / keep.
6. Аффиксный fallback (защита от одинокого 3-суффикса) — только если n-граммы
   не против (`AffixMinAdvantage`).
7. Контекст: слово из 1–2 букв после слова той же раскладки не трогается.

**Порядок live-решения** (`TryLiveConvert` → `LayoutDecisionEngine.DecideLive`):
1. reverted-word lock (слово, отменённое Pause'ом, не трогать).
2. oscillation guard (видимое all-letters ↔ converted с non-letter краем).
3. hit: LiveTrigger, иначе n-граммы (видимое начало «невозможно», converted — нормально).
4. двусторонний LiveTrigger (обе формы известны своим языкам) → оставить visible.
5. hold: видимое начало — частое слово текущего языка, или (для trigger-hit)
   читается как нормальное начало слова → ждать final.
6. user guards: UserDictionary (обе формы) + UserReplacement (только visible).
7. → `PerformLiveReplace`.

## Критические инварианты (баги, которые уже ломали и не должны вернуться)

Эти правила выработаны кровью на версиях 1.5.0–1.5.8. **НЕ нарушай их,**
меняя логику. Если кажется, что надо нарушить — скорее всего ты создаёшь один
из уже исправленных багов. Подробности и номера версий — в `CHANGELOG.md`.

1. **Live-путь считает N−1 backspace.** Низкоуровневый хук срабатывает ДО
   доставки клавиши в приложение, поэтому в буфере уже N символов, а в
   приложении N−1. Нужно шлёпнуть N−1 backspace, затем полный converted, и
   установить `args.Suppress = true`, чтобы клавиша-триггер не дошла дважды.
   (Регресс: «привет руддщ → приветhelllo», фикс в 1.5.1.)

2. **Live проверяет только «живые» клавиши.** Backspace/Delete и ЛЕВЫЕ/ПРАВЫЕ
   модификаторы (VK 0xA0–0xA5, Win 0x5B/0x5C) НЕ должны запускать live-чек —
   см. `IsLiveEligibleKeystroke`. Иначе нажатие Ctrl само по себе
   переключает «зависшее» слово, а Backspace даёт ложные срабатывания на
   «обрезках». (Фикс в 1.5.5 и 1.5.6.)

3. **Revert блокирует повторную автоконвертацию того же слова.** После
   ручного отката (Pause) `ConversionService._revertedWord` хранит видимое
   слово, и `TryLiveConvert`/`FinalConvert` его пропускают, пока слово не
   изменится. Без этого — цикл «live→revert→final→revert». (Фикс в 1.5.6.)
   С 1.10.1 ту же блокировку ставит и ручная конвертация Break: `it` →
   Break → `ше` → пробел не должен вернуть `it`. Когда пользователь начинает
   следующее слово, блокировка переходит в `_previousWordLock` (см. инв. 37).

4. **Системные аббревиатуры исключены из триггеров.** В `TriggerDictionaries`
   есть `SystemAbbreviations` (`ctrl`, `alt`, `tab`, `esc`, `f1..f12`…). Без
   этого набор `Секд` на RU переключал в `Ctrl`. (Фикс в 1.5.6.)

5. **Аффиксный fallback не доверяет одинокому 3-буквенному суффиксу.** В
   `AffixModels.Score` суффикс длиной 3 без префикса игнорируется — иначе
   `ger` срабатывает на бессмысленном `ueger`. Нужен префикс, суффикс ≥4,
   или их сумма. (Фикс в 1.5.5.)

6. **Live-oscillation guard.** Если видимый токен из одних букв, а его
    converted-форма получила non-letter на краю (буква смапилась в знак,
    например `б`↔`,`) — НЕ проверять такой converted через `TrimNonLetters`.
    Иначе `будь`↔`,elm`↔`elm` делает бесконечную осцилляцию. (Фикс в 1.5.7.)
    Это правило также применяется к словам с пунктуацией по краям на live-пути:
    `"было"` не должно live-схватываться на середине как `sk` и улетать в
    `@,skj@`; такие случаи должен решать только final после полного wrapper-а.

7. **UserDictionary ≠ UserReplacement.** Словарь — приоритетный **Final**
   словарь раскладки, проверяет ОБЕ формы. Замена — **exact visible**
   replacement, converted-форму НЕ проверяет (запрещена цепочка
   `gynh→пнтр→фраза`). Их нельзя смешивать. (Спецификация в
   `docs/ARCHITECTURE.md`.)

8. **LiveTrigger поднимается раньше полного слова только когда guard согласован.**
   Если в UserDictionary есть длинное слово, начинающееся с того же префикса,
   что и live-trigger, live должен сработать рано ТОЛЬКО когда словарное слово
   лежит в целевой раскладке (согласовано с hit). Если в текущей — ждать
   (пользователь, возможно, печатает именно его). (Фикс в 1.5.4.)

9. **Конвейер `SwitchTo`/`PostSwitchTo`.** Всё, что выполняется внутри хука
   (live и, с 1.9.0, final через `InputBatch`), переключает раскладку
   `LayoutSwitcher.PostSwitchTo` — без sleep, fire-and-forget (синхронность хука
   гарантирует доставку раскладки до следующей клавиши).
   `SwitchLayoutPreservingForeground` сам это учитывает
   (`TextInputSender.IsBatching`). Ручные команды из фонового потока (Break,
   выделение) по-прежнему используют `Thread.Sleep(40)` и проверку смены окна.
   **Никогда не делай Sleep внутри хука.**

10. **Очистка source.** В source-снапшот не входят `tools/`, корневые
    словари `30k-english.txt`/`50000-russian-words-cyrillic-only.txt` и
    экспериментальные проекты. `tests/`, `LICENSE`, `NOTICE.md` входят.
    Таблицы в `Resources/Dictionaries` — производные данных сторонних
    словарей и **не** подпадают под MIT: их условия описаны в `NOTICE.md`. Скрипт `build.ps1 -Variant source` собирает
    его правильно — не правь руками список файлов без необходимости.

11. **Final не должен доверять trimmed-форме раскладочной пунктуации.** Если
    буквенное ядро видимого слова состоит только из букв, а его converted-форма
    получила дополнительный небуквенный край из-за маппинга (`б`→`,` /
    `,ele`→`ele`), final-логика не должна использовать обрезанный lookup
    противоположной раскладки для FinalTriggers/аффиксов. Иначе корректное
    русское `буду` превращается в `,ele`, `были,` — в `,skb?`, а `"сек"` — в
    `@ctr@` только потому, что `ele`/`skb`/`ctr` есть в английских триггерах.
    **Исключение:** UserDictionary — явный пользовательский приоритет; если
    пользователь добавил `github`, то `пшерги,` должно конвертироваться в
    `github?`, а `ЭпшергиЭ` — в `"github"`. Но UserDictionary не должен
    доверять trimmed converted-форме с сгенерированным ведущим мусором:
    `"было"` не должно стать `@,skj@`, даже если `skj` случайно оказался в
    пользовательском словаре.
    **Исключение 2:** парные wrapper-знаки (`"..."`, `'...'`, `[...]`,
    `{...}`, `(...)`, `<...>`) разрешены для обычных final-триггеров: например
    `ЭруддщЭ` должно конвертироваться в `"hello"`.

12. **Выключенный AutoMode отключает обучение ручного Break/Pause.** Ручная
    конвертация последнего слова должна оставаться доступной всегда, но если
    пользователь выключил автопереключение, она не должна молча добавлять слово
    в UserDictionary и не должна показывать prompt «запомнить». Это режим
    разовой ручной правки, а не обучения автологики.

13. **Backspace/Delete переоткрывает live-анализ только для следующего ввода.**
    Само стирание не должно запускать live-проверку на обрезке слова, но оно
    обязано снять `_currentWordHadLiveTrigger`: пользователь мог исправлять
    слово после ошибочного автопереключения, и следующая добавленная буква должна
    снова получить шанс переключить раскладку. При этом tracked deletion не
    очищает `_revertedWord`, если изменился только trailing-разделитель, а само
    слово после ручного Pause-revert осталось тем же.

14. **Двусторонний LiveTrigger не выбирает раскладку.** Если visible-форма
    является live-триггером текущего языка, а converted-форма одновременно
    является live-триггером другого языка (`ищу` ↔ `boe`), сигнал неоднозначен:
    live-путь обязан оставить видимый текст как есть. Иначе корректное слово в
    любой из двух раскладок автоматически прыгает на другую сторону.

15. **Автозаглавная буква — отдельный слой отмены над раскладкой.**
    `AutoCapitalizeLastWord` не должна перезаписывать `_lastConversion`.
    `ConvertLastWord` сначала проверяет `_lastCapitalization`: первый Break
    возвращает только строчную букву, второй использует сохранённую историю
    раскладки, последующие переключают раскладку как обычно. При успешной
    автозаглавной и её отмене буфер нельзя очищать настройкой
    `ClearBufferAfterConversion`, иначе следующий шаг Break потеряет контекст.

16. **Регистр и транслит работают selection-first.** Если реально выделен
    текст, меняется только выделение; последнее слово используется лишь когда
    выделения нет. Если выделение есть, но прочитать его не удалось, нельзя
    молча переходить к последнему слову. После изменения выделения буфер
    очищается, после изменения последнего слова — синхронно обновляется.
    Зарегистрированные hotkey-сочетания пропускаются в `KeyObserved`, а ручная
    отправка текста ждёт отпускания Ctrl/Alt/Shift/Win: иначе модификатор может
    очистить буфер или превратить инжектированный Backspace в Ctrl+Backspace.

17. **Не используй модифицированный Pause/Break как дефолтный hotkey.**
    Windows различает `VK_PAUSE` и `VK_CANCEL` (Ctrl+Break), а ноутбучные
    клавиатуры дополнительно меняют код через Fn. Надёжные дефолты регистра и
    транслита — `Ctrl+Shift+F9` и `Ctrl+Shift+F10`; значения 1.7.0
    `Ctrl+Pause`/`Alt+Pause` мигрируют в `AppSettingsService.Normalize`.

18. **Все selection-команды используют единый безопасный reader.**
    `SelectionProbe.TryReadSelectedText` сначала ищет `TextPattern` у
    сфокусированного UIA-элемента и его родителей, затем пробует `WM_COPY` и
    `Ctrl+Insert`, но clipboard-fallback разрешён только при
    `_selectionIntent`. Intent ставится после mouse-drag/double-click,
    Shift+navigation или Ctrl+A и снимается обычным кликом/вводом/навигацией.
    Whitespace-only UIA range не считается выделением. Не возвращай без
    отдельного доказательства обычные `Ctrl+C` или `Ctrl+Shift+C`: редакторы
    могут скопировать строку, ссылку или путь без выделения.

19. **Обратный транслит неоднозначен и работает консервативно.**
    `TextTransformationService.Transliterate` выбирает направление только для
    текста одного алфавита; смешанная кириллица+латиница остаётся без изменений.
    Reverse-парсер проверяет длинные последовательности до одиночных букв.
    Одиночный `y` означает `ы` после согласной и `й` в начале/после гласной.
    Не обещай точный round-trip для `й/ы`, `е/э`, `ь/ъ`: текущая прямая таблица
    теряет эти различия.

20. **Ручной SendInput ждёт отпускания модификаторов намеренно.**
    Не убирай `WaitForHotkeyModifiersReleased` ради мгновенного отклика:
    удерживаемые Ctrl/Alt/Shift/Win меняют смысл Backspace и могут удалить слово,
    вызвать Undo или навигацию. Команда должна сработать сразу после отпускания.

21. **Исправление Caps Lock требует двух независимых признаков.**
    `FixAccidentalCapsLock` работает только когда системный Caps Lock фактически
    включён И завершённое слово имеет форму `пРИВЕТ`: первая буква строчная,
    остальные буквы заглавные. Обычные `привет`, `Привет`, `ПРИВЕТ` и смешанный
    регистр не меняются. Этап идёт после final-конвертации раскладки, но до
    автозаглавной буквы; пользовательские замены пропускаются. После успешной
    нормализации Caps Lock выключается.

22. **У изменения регистра два явных режима.**
    При `InvertEachCharacterCase == false` сохраняется историческое поведение:
    весь текст становится верхним регистром, а полностью верхний — нижним.
    При `true` каждая буква инвертируется отдельно (`Привет` → `пРИВЕТ`).
    Не выводи один режим из формы слова и не смешивай эту настройку с
    автоматическим исправлением Caps Lock.


23. **«ё» в поиске по триггерам — только в одну сторону.** Записи таблиц не
    нормализуются `ё`→`е`: `шё` (клавиши `` i` ``) и `ше` (`it`) — разные
    последовательности клавиш. Запрос с `ё` может найти запись с `е`, но не
    наоборот. Нормализация обеих сторон в 1.8.1 превращала `it`, `at`, `other`
    в кириллицу (2,6 % ложных исправлений английского текста).

24. **Разделитель обрабатывается синхронно в хуке через `InputBatch`.** Буфер
    уже содержит разделитель, приложение — нет. Шаги конвейера правят хвост
    буфера, пакет сводит правки к «N backspace + текст» относительно экрана.
    Нет изменений → клавиша проходит как есть. Есть → `args.Suppress = true`
    и один `SendInput` с текстом и самим разделителем (`\n` → VK_RETURN,
    `\t` → VK_TAB). Ошибка отправки → буфер сбрасывается, клавиша проходит.
    Не возвращай `Task.Run` для разделителя: это вернёт гонку с быстрым
    набором и «Enter отправил опечатку раньше исправления».

25. **Одна замена — один `SendInput`.** Любая замена (live, final, ручная)
    уходит одним массивом событий: так Windows не перемешивает её с
    физическими нажатиями. Не отправляй символы по одному.

26. **Видимая форма для частот/n-грамм/live-hold — выровненная.** Конвертация
    посимвольная, поэтому для converted-ядра берётся ровно тот же отрезок
    видимого текста (`AlignedSlice`): для `бы` это `,s`, а не обрезанное `s`.
    Иначе одиночная «буква» `s` выглядит частым английским словом и блокирует
    исправление.

27. **N-граммы сравниваются только в относительных оценках** (`NgramScore.Relative`
    = средняя log-вероятность минус типичная для слова той же длины в своём
    языке). Сырые log-вероятности русского (33 буквы) и английского (27)
    несравнимы: без нормировки модель систематически «болела» за английский.

28. **Поля пароля, исключённые программы, полноэкранные окна.** В поле пароля
    клавиши даже не попадают в буфер и журнал. Автоматические правки (live,
    final, автозамена, регистр) выключены там, в исключённых программах и в
    полноэкранных окнах без рамки; пока проверка фокуса не завершилась
    (`IsProbePending`, ≤ 800 мс), правки тоже ждут. Ручные горячие клавиши
    работают везде. Проверка UI Automation — только в фоновом потоке
    `InputContextGuard`, никогда в хуке.

29. **Третья раскладка — не трогать.** Язык раскладки определяется по
    первичному языку (`LayoutProbe.LanguageOf`): все английские варианты —
    English, все русские — Russian, прочие — Unknown. При Unknown final не
    работает (live не работал и раньше). При переключении берётся уже
    установленная раскладка того же языка; `LoadKeyboardLayout` — только если
    такой нет совсем.

30. **Данные пользователя пишутся только через `AtomicFile`.** Временный файл +
    `File.Replace` с `*.bak`; нечитаемый файл откладывается как
    `*.corrupt-<дата>` и заменяется резервной копией, а не перезаписывается
    пустыми данными.

31. **Пороги и таблицы меняются только с замером.** После правки
    `NgramDecisionOptions`, ручных списков `tools/LayoutFixer.Tools/data/*`
    или порядка решений прогоняй `LayoutFixer.Tools eval` (сравни с таблицей в
    `tools/LayoutFixer.Tools/README.md`) и `dotnet test`. Ложное исправление
    правильного слова хуже пропуска: при выборе порогов ориентируйся прежде
    всего на число ложных срабатываний.

32. **Проверка обновлений — только чтение и только вне хука.** `UpdateChecker`
    делает один GET к GitHub API (без данных пользователя, только
    `User-Agent` с версией), не скачивает и не запускает файлы; ссылка
    открывается в браузере, только если ведёт в репозиторий проекта.
    Проверка асинхронная и стартует с UI-потока (`UpdateCoordinator`), никогда
    из хука. Автоматическое уведомление — неактивирующий `TrayPrompt`: окно,
    отнимающее фокус, посреди набора текста недопустимо. Выключенный
    `CheckForUpdates` означает «ни одного сетевого запроса без явного
    нажатия пользователя».

33. **Новое свойство `AppSettings` → добавь его в `CopyFrom`.** Иначе
    «Импортировать всё» молча его потеряет (так в 1.9.0 терялись исключения,
    звук и ДВе ЗАглавные). Тест `BackupRestoreCopiesEverySetting` требует
    заполнить новое свойство в тесте небазовым значением.

34. **Настройки — в окне настроек, данные — в своих окнах.** Окна словаря и
    замен — редакторы данных без собственных тумблеров (автозамена и учёт
    пунктуации живут в «Словари и замены», быстрый тумблер — в меню трея).
    Одна настройка — один контрол в окне настроек; изменения извне
    синхронизируются через `RefreshFromSettings`, а не дублированием.

35. **Конвейер разделителя работает один раз на слово.** Если после слова
    уже был разделитель (`слово␣␣`, `слово -`, `слово\n\n`,
    `BufferToken.HasEarlierTerminator`), следующий разделитель не запускает
    ни замену, ни final, ни исправления регистра. Иначе сценарий «пробел →
    Break → пробел» заново решал судьбу слова и отменял ручную правку, а
    повторный `Enter` переделывал слово предыдущей строки. `слово! ` —
    не повтор: `!` сам конвейер не запускает. (Фикс в 1.10.1.)

36. **Caps Lock: решение о раскладке — по задуманному регистру.** Если
    Caps Lock включён, `FinalConvert` передаёт движку
    `NormalizeAccidentalCapsLock(слово)`: `dSGBIB` оценивается как `Dsgbib`,
    а не как идентификатор `VkShift`. Замена сохраняет набранный регистр
    (`вЫПИШИ`), регистр правит следующий шаг `FixAccidentalCapsLock`, который
    синхронизирует `_lastConversion` — Break откатывает к `Dsgbib`. При
    выключенном Caps Lock правило идентификаторов не меняется. Ручной Break
    не предлагает запомнить слово, которое движок и так распознаёт сам
    (`ConversionOutcome.AlreadyRecognized`). (1.10.1.)

37. **Одиночная буква меняет раскладку вместе со следующим словом.**
    Контекстное правило оставляет `b` в `plan b`, поэтому `hello z` не
    становится `hello я`. Когда следующее слово конвертируется (live или
    final), предыдущая однобуквенная лексема через одни пробелы меняется
    вместе с ним: `hello z levf` → `hello я думаю`. Только строчная буква,
    которая слово в целевом языке и не слово в исходном (EN d/f/z/b/c/e/j/r
    ↔ RU в/а/я/и/с/у/о/к, RU ф/ш → EN a/i, а также `Ш` → `I`), не из
    UserDictionary и не выбранная пользователем вручную (`_previousWordLock`).
    Слово, заканчивающее предложение (`.`, `?`, `…`, `!`), или перевод строки
    (новое сообщение в чате) не дают контекста следующему. (1.10.1.)

38. **Русский текст полон английских терминов.** Настройка
    `AlwaysConvertSingleLetters` («Всегда исправлять в, а, я, и, с, у, о, к»,
    по умолчанию включена, с 1.11.0) снимает контекстное правило для строчной
    буквы EN d/f/z/b/c/e/j/r полностью: `ok z` → `ok я`, `plan b` → `plan и`.
    Если её выключить, правило «буква после слова той же раскладки не
    меняется» срабатывает только после обычного строчного английского слова
    (`plan b`) в предложении без кириллицы (`GetSentenceBeforeLastToken`). После имени или
    термина с заглавной (`Claude b ChatGPT`, `API b SDK`) или в русском
    предложении (`Сравни docker b kubernetes`) буква исправляется, но
    **раскладка не переключается** (`TermLetterSource`): следующий термин,
    скорее всего, английский, а `ФЗШ`/`СрфеПЗЕ` восстановить труднее, чем
    русское слово. Заглавная буква (`plan B`) не трогается.
    Аббревиатуры ВСЕ-ЗАГЛАВНЫМИ (`ФЗШ`) не оцениваются в нижнем регистре:
    замер дал 11 ложных из 150 русских (`ОМС`, `МФЦ`, `РФ`). (1.10.1.)

39. **Смешанный регистр в кириллице — не идентификатор.** `СрфеПЗЕ` —
    это `ChatGPT` в русской раскладке. Если видимое слово кириллическое и обе
    формы имеют «внутреннюю» заглавную, final решает по строчной форме
    (`МегаФон`, `СберБанк` так остаются). Для латиницы (`iPhone`, `VkShift`)
    правило идентификаторов прежнее. (1.10.1.)

## Правила правок (из docs/CONTRIBUTING.md, кратко)

- **Перед правкой логики переключения** — прочти инварианты выше и
  `CHANGELOG.md` за последние 5–6 версий. Почти любая «очевидная» правка
  ломает один из уже исправленных кейсов.
- **Бамп версии** — только в `src/LayoutFixer/LayoutFixer.csproj` (`<Version>`).
  Формат `MAJOR.MINOR.PATCH`; мелкие фиксы — PATCH, существенные — MINOR.
- **CHANGELOG обязателен** для каждого релиза. Пиши по-русски, рубрики
  `### Добавлено / ### Изменено / ### Исправлено / ### Удалено`.
- **Не добавляй полные словари обратно** в csproj/`WordDictionaries` — от
  них сознательно ушли в 1.5.0. Триггеры и аффиксы предгенерированы.
- **Тестируй вручную** по `debug.log`: собрал win-x64 → запусти →
  воспроизвёл кейс → смотрю `TryLiveConvert`/`FinalConvert` решения в логе.
- **Не встраивай данные чужих программ** (таблицы, словари, звуки) — только
  собственные или с совместимой лицензией, с записью в `NOTICE.md`.

## История принятия решений (почему так, а не иначе)

- **Почему триггеры, а не полные словари в runtime?** Полные словари давали
  score-логику, которая на коротких словах и аффиксах часто ошибалась и была
  медленной. В 1.5.0 перешли на предгенерированные LiveTriggers/FinalTriggers
  + аффиксы как fallback. Runtime теперь делает только membership-проверки.
- **Почему live-путь синхронный на хуке?** `WH_KEYBOARD_LL` вызывается на
  UI-потоке синхронно: пока callback не вернётся, следующая клавиша не
  диспетчируется → гонок с буфером нет. Это позволяет подавить
  клавишу-триггер через `args.Suppress` и сразу синхронно заменить текст.
  Final-путь идёт через `Task.Run`, т.к. слово уже целиком видно и допустимо
  подождать foreground-проверку.
- **Почему у live отдельная `PostSwitchTo`, а не `SwitchTo`?** `SwitchTo`
  ждёт 40 мс и проверяет смену окна — на горячем live-пути это лишнее
  (замена идёт Unicode, раскладка нужна только следующей клавише).
- **Почему `PerformLiveReplace` отдельно?** Чтобы user-dict path и
  trigger-path делили одни и те же механики (N−1 backspace + suppress).
- **Почему в 1.9.0 появились n-граммы и частоты коротких слов, а не полные
  словари?** Триггерные таблицы покрывают только «запомненные» слова и не
  знают форм слов; полные словари в runtime дали бы прежние проблемы (мусорные
  аббревиатуры, медленная score-логика). Триграммная модель — компактная
  статистика (≈200 КБ), которая обобщается на любые словоформы, а частоты
  коротких слов решают самые частые и самые неоднозначные случаи (`yt`/`не`,
  `it`/`ше`). Идея та же, что у классических переключателей раскладки
  («невозможные» буквосочетания), но оценки вероятностные, а не ручные списки.
- **Почему final теперь в хуке?** Слово к моменту разделителя уже целиком
  в буфере, решение — микросекунды, отправка — один `SendInput`. Асинхронный
  вариант с `Sleep(40)` терял клавиши, набранные в это окно, и не успевал
  исправить слово до того, как `Enter` отправлял сообщение.
